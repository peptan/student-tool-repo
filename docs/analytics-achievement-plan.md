# 旧・通算達成と分析の設計（廃止）

> 初回・難易度・到達状況を含む旧仕様です。現在は `docs/simple-learning-record-plan.md` の単純な正解数・正解率仕様へ移行済みです。

## 追加する記録

既存の「現在の10問セット」の到達状況とは別に、ブラウザ内で通算の学習記録を保持する。

- **変換方向別・初回正解率**：各10問セットを最初に解いた結果だけを累積する。復習結果は分母・分子に混ぜない。
- **通算で正解した問題**：これまで最初に解いた全問題に対する正解数を `正解数 / 問題数` で表示する。復習結果は混ぜない。

## 画面

- メニューには「学習の分析を見る」を追加する。
- `analytics.html` に、通算正解数（何問中か）と変換方向別の初回正解率を棒グラフで表示する。
- 初回 `1/10`、復習 `1/9` の例では、現在セットの到達状況 `2/10 (20%)` と、通算初回正解率を別項目にする。

## 出題順

10問は内部的に、1〜4問目・5〜8問目・9〜10問目の3段階で出題する。画面ではビット数・難易度名を繰り返し表示しない。

## 保存の移行

旧形式は、復習用の誤答を保ち、現在セットの初回成績が復元できる場合だけ通算初回成績へ移す。不明な旧集計値を新しい指標へ混ぜない。

## 受入条件

1. 新しい10問を複数回解くと、変換方向別の初回正解率が累積する。
2. 復習の正解は通算初回正解率を変えない。
3. 通算正解は、これまで最初に解いた全問題に対する `正解数 / 問題数` で表示する。
4. 分析画面はデータなし・データありの両方で読み取れる。
5. 問題文は4択を示す表現、採点結果はコンパクト表示、不正解は赤系にする。

## 検証ログ

- 自動確認：`npm test`（14件成功、通算 `7 / 40問` の集計を含む）、`npm run check`、`git diff --check` を実行。
- ローカル実ブラウザ：データなしの分析画面、通算カードの説明文、コンソールエラーなしを確認。既存の学習記録はユーザーのブラウザにのみあるため、値 `7 / 40問` は保存データを模した自動テストで検証。
